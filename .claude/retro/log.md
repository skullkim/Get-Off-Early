# 하네스 회고 로그

`retrospective` 스킬이 매 프로젝트 빌드 후(또는 수동 호출 시) 이 파일에 회고 항목을 append 한다.
각 항목은 그 시점에 발견한 신호와, 그에 따라 하네스/메모리에 반영한 변경을 기록한다.
이 로그의 목적은 **진화 궤적 추적**과 **퇴행 방지**다 — 과거에 내린 결정을 모르고 되돌리지 않도록 한다.

형식:
## {날짜} — {프로젝트명}
- 신호: {무엇을 관찰했나}
- 일반화: {원리 수준 교훈}
- 반영: {수정한 파일/메모리}
- 보존: {건드리지 않기로 한 좋은 패턴}
- 지표: QA 라운드 N · blocker/major n/n · 리더 takeover 유/무 · 게이트 드리프트 n · 계약 에스컬레이션 n · 모델 <명> (빌드 회고면 필수 — 추세 비교용 고정 형식; 모델 필드로 모델 교체 전후를 구분)

## 2026-06-14 — Todo 앱 라이브 테스트: CORS 403 / 실제 E2E 부재 (추가 회고)
- 신호: "QA 4라운드 통과 + 빌드 완료" 선언 후, 사용자가 실제 브라우저(cloudflared 터널)로 가입하자 **403 "Invalid CORS request"** → 프론트 "일시적 오류". 근본: 백엔드 CORS allowlist가 `localhost:5173/3000`만 허용, 터널 origin 거부.
- 왜 안 걸렸나: MSW(가짜 네트워크) + MockMvc(서블릿/CORS 필터 우회) + 계약-읽기 QA + curl(Origin 미전송)이 **전부 브라우저 실제 HTTP 의미를 우회**. 진짜 브라우저↔진짜 백엔드 E2E가 워크플로우에 없었고, 같은 날 추가한 "리더 독립검증"도 목 스위트+curl이라 동일한 사각.
- 일반화: 브라우저 프론트 + 별도 백엔드는 목/슬라이스/계약읽기/curl이 모두 그린이어도 CORS·프리플라이트·헤더/쿠키·리다이렉트·mixed content에서 깨질 수 있다 → **완료 선언 전 실제 브라우저↔실제 백엔드 1회 E2E 스모크 필수. curl ≠ 브라우저.**
- 반영: `qa-verification`에 "라이브 E2E 스모크" 필수 섹션 + "목 그린 ≠ 실제 통합" 원칙 / `build-project` Phase 6 리더 독립검증에 실제 앱 E2E 추가 / `architecture-and-delegation` 계약 하드닝에 cross-origin/CORS 항목. 메모리 `verify-web-apps-in-real-browser` 저장.
- 수정: dev fix로 Vite 프록시가 백엔드 전달 시 Origin 헤더 제거(`vite.config.ts`) → 터널 403→201 확인(헤드리스 CDP 재현). 백엔드 prod CORS는 의도대로 유지.
- 퇴행 점검: 오늘 추가한 "리더 독립검증(테스트 실행)"을 되돌리지 않고 **정제**(테스트 실행 + 실제 앱 E2E)함. 충돌 없음.

- **소유한 것을 바꿔 소유하지 않은 것을 나쁘게 만들었다**: 앱이 `Normal` 배경을 덮으면서(우리 권한) 우리가 바르지 않는 `LineNr`(nvim 기본 `#4F5258`)의 대비가 **2.34 → 2.19** 로 내려갔다(§4.5 바닥 4.5의 절반. 리더가 독립 계산으로 검증). **두 결정 각각은 옳은데 사이에서 하나가 나빠졌고, 그 나빠짐은 어느 결정 문서에도 없다** — 각자 자기 범위만 봤기 때문이다.
- **"예외"와 "갭"을 갈랐다**(리더 판정): 목록에 **없는 것**과 **안 하기로 결정한 것**은 다른 사건이다. 프로토타입이 `~` 를 `text-3` 로 약속해 놓고 구현 목록에서 빠졌으면 그건 예외가 아니라 갭이다. **"예외"는 다음 사람이 안 보고 "갭"은 본다.**
- **열거를 전수처럼 쓰는 것이 이 빌드의 지문**: 원인 후보를 둘로 열거했는데 답이 셋째(nvim 인트로 화면)였다. `route()` catch-all · `failure(for:)` default 에 이어 **원인 목록**에서도 같은 형태. → 처방: 열거 옆에 **"확인된 것만이고 전수가 아니다"** 를 박는다(PD 가 판정기 라벨에 적용).
  - **그리고 셋 다 "자기가 가장 잘 아는 자리"에서 어겼다**(PD 관찰): 프론트는 빈 집합 단언을, 리더는 자기가 만든 근거 붕괴 표를, PD는 색↔그룹 매핑을. **가장 잘 아는 영역이라 확인을 건너뛴다.** → 그래서 처방이 "도구로 옮기기"인 것이 맞다 — **도구는 익숙함에 안 진다.**
