# 에러 핸들링 — 상황별 전략

> `build-project` 스킬의 참조 파일. 본문에서 떼어 둔 이유는 이 내용이 **특정 국면에서만** 필요하기 때문이다 — 스킬이 트리거될 때마다 컨텍스트에 올리지 않는다.

## 에러 핸들링

| 상황 | 전략 |
|------|------|
| 요구사항 모호/모순 | Phase 1에서 사용자에게 확인. 하류 진행 전 닫는다 |
| 스택 결정 교착 | 시니어가 2~3안 + 근거 제시, 리더가 사용자에게 확인 |
| TDD 게이트 미충족인데 QA로 넘어옴 | QA가 즉시 개발로 반려. 게이트 우회 금지 |
| API 계약 불일치(경계면) | QA가 양쪽 시니어에게 동시 통지, 계약 재합의 후 양쪽 수정 |
| 계약 협상 교착(시니어 상호 양보로 교차/2회 불일치) | 백엔드 파일 §3가 단일 소스. 리더가 값을 정해 **파일에 동결**(메시지 말고 파일이 권위), 양쪽에 "더 조율 금지" 통지 |
| 팀원 1명 실패/중지 | 리더가 유휴 알림 감지 → SendMessage 상태 확인 → 재시작, 실패 시 작업 재할당(시니어/리더) |
| QA 루프 무한 반복 | 2라운드 연속 진전 없음 → 사용자 에스컬레이션 |
| 팀원 과반 실패 | 사용자에게 알리고 진행 여부 확인 |
| **팀 stall / hang (★ 안전장치)** | 리더가 하트비트마다 활동 점검(파일 mtime·작업 목록 상태 열·게이트 결과). **N회(예 2~3) 무활동 + 핑/shutdown 무응답 = hang 판정**: ①프로세스 생존 확인(`pgrep -fl "agent-id.*session-…"`) ②**hung 에이전트 kill**(`pkill -f "agent-id.*session-…"`) — 생존 가정 시 gradle/Docker 충돌 위험이라 kill 전 직접 실행 금지 ③**리더가 직접 마무리**(코드 상태를 *테스트 실행으로* 검증 후 잔여 수정·게이트) 또는 **격리 잔여작업만 단일 신규 에이전트 재스폰**(cross-dep 없는 단일 태스크는 데드락 안 남). 실제 발생: 멀티에이전트 빌드 후반 아이들 데드락→완전 hang, 리더 takeover로만 완성. cron 하트비트가 stall 탐지기 역할([[auto-resume-long-builds]]). |
