# Harness Runtime Adapter — 런타임 종속부 매핑 (단일 소스)

이 하네스의 절차(스킬)는 **역할(role)**로 서술하는 것을 지향하고, 역할이 어떤 런타임 도구에 대응하는지는 **이 표가 단일 소스**다.
런타임(Claude Code → 다른 에이전트 CLI)을 교체할 때 고치는 곳이 이 표 한 장에 머무는지가 이식성의 판정 기준이다.

## 역할 → 도구 매핑 (현재 런타임: Claude Code)

| 역할 (스킬에서 쓰는 이름) | Claude Code 도구 | 용도 |
|---|---|---|
| 에이전트 스폰 | `Agent` (named spawn, subagent_type) | 팀원 생성 (model 미명시 = 세션 상속) |
| 격리 스폰 | `Agent`의 `isolation: "worktree"` | 독립 배치를 워크트리로 격리 병렬 (미변경 시 자동 정리) |
| 팀 통신 | `SendMessage` | 팀원 간 / 리더↔팀원 메시지 |
| 작업 목록 | `TaskCreate` / `TaskList` / `TaskUpdate` | 위임 작업 등록·추적 |
| 사용자 질문 | `AskUserQuestion` | 요구사항 인터뷰·승인 |
| 예약 실행 | `CronCreate` / `CronDelete` | 자동 재개 트리거 |
| 세션 시작 훅 | SessionStart hook (`settings.json`) | 재개 지시 주입 |
| 스킬 호출 | `Skill` | 절차서 로드 |
| 파일 IO/검색 | `Read` / `Write` / `Edit` / `Grep` / `Glob` | 공통 |
| 셸 실행 | `Bash` | 게이트·빌드·실측 |

## 운영 규율 (점진 적용)
- 스킬을 **새로 쓰거나 수정할 때**, 런타임 도구명을 쓰는 자리에는 가능하면 역할명을 병기한다 — 예: "`TaskCreate`(작업 목록)로 등록".
- 전면 소급 치환은 하지 않는다 — 수정이 닿는 부분부터 점진적으로.
- 런타임 교체 시: 이 표의 도구 열만 갱신하고, 스킬의 역할명을 새 매핑으로 해석한다. 스킬 본문을 대량 수정해야 한다면 그 부분이 "런타임 종속부 누수"이므로 회고에서 격리 대상으로 올린다.
- **판정 기준**: 런타임 교체 작업에서 고친 파일이 이 표 + 소수 스킬 라인에 머무는가. (모델 교체가 "설정 변경 수준"이어야 하는 것과 같은 원칙 — 모델명·도구명을 하네스에 하드코딩하지 않는다.)
