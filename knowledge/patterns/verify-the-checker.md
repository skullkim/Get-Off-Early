# 문제
"무언가를 잡아내는 검사"(시크릿 스캔, 계약 드리프트 검사, 린트 룰, 커버리지 임계)는 **조용히 실패한다**. 테스트는 실패하면 빨간불이 뜨지만, 검사기가 아무것도 잡지 못하는 상태는 **초록불과 구분되지 않는다**. 통과가 곧 안전이라고 믿는 순간 방어선은 장식이 된다.

실제 사고: 게이트의 시크릿 스캔이 세 가지 결함으로 침묵 통과 중이었다.
1. `grep --include='*.{ts,js}'` — 브레이스 glob이 셸이 아닌 grep 인자로 넘어가 확장되지 않아 **검사 대상이 0건**
2. `-i` 부재 — `apiKey` 같은 camelCase를 소문자 패턴이 놓침
3. 허용목록 파일이 비어 있을 때 `grep -vFf <빈파일>` 이 **결과 전체를 삼킴**

세 결함 모두 "스캔은 실행되고 종료 코드 0"이라 완벽히 정상으로 보였다.

# 해법
**리크 픽스처로 양방향 실측한다.**

```
1. 검출되어야 할 샘플(가짜 API 키·토큰 등)을 임시 파일에 심는다
2. 검사 실행 → 비0 종료 + 해당 파일이 보고에 나오는지 확인   ← 잡는가
3. 샘플 제거 후 재실행 → 0 종료                              ← 오탐 없는가
4. 픽스처 정리
```

이 절차를 **검사기를 작성한 직후 1회**, 그리고 **검사기를 수정할 때마다** 수행한다. 통과만 확인하는 것은 절반이다.

# 적용 대상
시크릿 스캔 · 계약/스키마 드리프트 검사 · 의존 방향 검사 · 마이그레이션 동반 검사 · 커버리지 임계 · 커스텀 린트 룰 — **"없어야 할 것이 없음"을 증명하는 모든 검사**.

# 일반화
방어선 실측(핵심 로직을 깨뜨려 테스트가 red가 되는지 확인)의 확장이다. 대상이 프로덕션 코드가 아니라 **검사 도구 자신**일 뿐이며, 검사기는 자기를 검증할 테스트가 없다는 점에서 오히려 더 위험하다. 관련: [[preflight-measure-as-consumer]]
