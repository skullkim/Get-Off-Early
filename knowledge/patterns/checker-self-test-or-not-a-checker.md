# 문제

빌드 판정에 쓰는 사실("결함 0건", "팀이 조용하다", "번들이 최신이다")의 상당수는 **대화 셸에 즉석으로 친 한 줄**에서 나온다. 그 한 줄은 테스트도, 리뷰도, 자기검사도 없다. 그리고 틀렸을 때 **에러가 아니라 초록을 돌려준다.**

실제 집계: 한 빌드에서 **검사의 사각이 아홉 번** 났다.

```
제네릭 뷰 선언 미매치 · 민감정보 3중 결함 · 숫자 형식 주석 오탐 · grep -cE '^/.*error:'
pgrep -c 부재 · --include 브레이스 글로브 · 격리 확인이 빌드 단계 누락
pgrep 경로 패턴 미매치 · find -newermt 를 2>/dev/null 로 삼킴
```

**원인은 셋으로 모인다:**

| | 유형 | 실례 |
|---|---|---|
| ① | 도구가 그 옵션을 지원하지 않는다 | `pgrep -c` · `find -newermt`(bfs) · `--include='*.{a,b}'` |
| ② | 패턴이 대상을 안 덮는다 | 번들 경로 · 제네릭 선언 · 이름 충돌 |
| ③ | 실패가 조용하다 | `2>/dev/null` · `grep -c '^/.*error:'` · `--filter` 0건 |

**결정적 관찰: `--self-test` 를 함께 가진 검사기에서는 사각이 한 번도 나오지 않았다.** 아홉 번 전부 **즉석 명령**에서 났다.

# 해법

**같은 질문을 두 번 이상 물을 것 같으면 즉석 명령을 스크립트로 승격하고, 자기검사를 같이 넣는다.**

```bash
check-x.sh --self-test    # 일부러 위반 픽스처를 심고 → 잡는지 확인 → 원복하고 0 종료 확인
check-x.sh                # 실제 판정
```

승격 판단은 간단하다: **그 명령의 출력이 판정 근거가 되는가.** 되면 스크립트다.

# 즉석 명령을 그대로 써야 할 때의 최소 규율

1. **`2>/dev/null` 을 판정 명령에 쓰지 않는다.**
   *실제 사고*: 팀 활동을 보려고 `find … -newermt '3 minutes ago' 2>/dev/null` 을 반복해 물었고 항상 0건이었다. 이 시스템의 `find` 는 `bfs` 라 상대 시각을 거부한다 — **명령은 실패하고 있었고, 그 에러를 스스로 지웠다.** "팀이 조용하다"를 여러 번 보고했지만 실제로는 4개 파일이 편집 중이었다.
   → **"결과 없음"과 "명령 실패"는 stderr 를 버리면 구별할 수 없다.** 소음 제거 목적일 때만 쓰고, 그때도 판정 근거로 쓰지 않는다.

2. **0건은 positive control 을 통과한 뒤에 믿는다** ([[verify-the-checker]]).

3. **디스크가 아니라 실행 중인 것을 본다.** 파일 mtime 은 "무엇이 돌고 있나"의 답이 아니다 — 돌고 있는 것은 `ps` 가 안다 ([[stale-dev-process]]).

# 보고서에 싣는 문장의 규율

같은 뿌리의 다른 얼굴: **보고서의 상태 문장은 그 보고를 쓰는 시점에 잰 것만 싣는다.** 앞 메시지에서 복사하지 않는다. 이전 관측을 언급해야 하면 **시각을 붙여 과거형으로** 쓴다.

이것이 근거 붕괴의 여섯 유형 중 마지막이다:

```
① 정적 분석을 실측으로 제시          ② 교란된 대조(재는 동안 대상이 변함)
③ 뒷받침 없는 단정                   ④ 남의 낡은 측정을 현재로
⑤ 잘린 출력을 전체로 읽음            ⑥ 자기 보고서에 자기 낡은 문장을 옮겨 실음
```

④와 ⑥이 다른 이유: **④는 남의 측정이 낡은 것이고, ⑥은 자기 측정을 자기가 갱신 안 한 것이다.**
